# План курса: SQL Sheet

Сводный план двух курсов на сайте: что готово, что дальше и что для этого нужно
доработать в тренажёре. Детали урока (теория, таблицы, задания) живут в `course.py`.
Состояние на 2026-11-11.

Готовые уроки описаны по `course.py`. Планы неготовых уроков — предложение:
на сайте у них пока только название и строка тем, с владельцем они не согласованы.
Пункты, которые надо решить с владельцем, собраны в «Открытых вопросах».

---

## Общие параметры

- **Два курса (трека) на одном сайте:** «Основы SQL» (`base`) и «SQL для аналитиков»
  (`analyst`). Номер урока на сайте считается по порядку внутри трека (`num` в
  `main.py`, `public_course`), а `id` — внутренний и не меняется: к нему привязаны
  прогресс и ссылки `?lesson=<id>`. Поэтому «Логический фундамент» — урок 2 на
  сайте при `id` 14.
- **СУБД:** PostgreSQL в браузере (PGlite). Тексты уроков описывают поведение PostgreSQL.
- **Языки:** EN (по умолчанию) и RU. Каждый текст урока — в обоих языках.
- **Формат урока:** теория → таблицы урока → задания с автопроверкой → «Следующий урок».
  Задания делятся на разделы (A, B, C…); дополнительная практика помечена `extra`.
- **Ответы видит только учитель** (вход внизу урока на `/lessons`).

### Виды заданий и как они проверяются

| Вид (`kind`) | Что делает ученик | Проверка на сервере (`/api/check`) |
|---|---|---|
| `sql` (по умолчанию) | Пишет запрос | Сверка результата с `course_results.json`: столбцы, число строк, значения; порядок — если в ответе есть `ORDER BY` (с учётом равных строк) |
| `value` | Выбирает TRUE / FALSE / NULL для выражения | Значение выражения на PostgreSQL |
| `truth` | Заполняет таблицу истинности | Каждая клетка |
| `rewrite` | Переписывает условие в другой форме (например, без `NOT` перед скобкой) | Значения на всех комбинациях + форма записи |
| `row` | Отвечает «пройдёт ли строка через WHERE» | Да/нет по реальному фильтру |
| `pick` | Отмечает строки, которые пройдут фильтр | Множество отмеченных строк |

- В треке аналитиков `check: values`: имена столбцов не важны, важны число и порядок
  столбцов и значения — вопрос приходит «от коллеги», и ученик сам решает, как назвать
  столбцы.
- После правки данных, ответов, примеров или условий — `make results` и коммит
  `course_results.json` вместе с `course.py`.
- **Ограничение проверки:** сервер сравнивает только результат `SELECT`. Для заданий
  на `INSERT` / `UPDATE` / `DELETE` / `CREATE` нужен новый вид проверки (см.
  «Доработки тренажёра»).

## Трек 1. Основы SQL

Для новичков: от первого `SELECT` до транзакций. Небольшие учебные таблицы
(8–12 строк) на урок, чтобы результат было видно целиком.

### Готово

**Урок 1. Введение в SQL и SELECT** ✅ (`id` 1)
- Темы: что такое SQL и реляционные СУБД, `SELECT`, `FROM`, столбцы.
- Таблицы: `students`, `books`.
- Заданий: 10 (`sql`).

**Урок 2. Логический фундамент** ✅ (`id` 14)
- Темы: TRUE и FALSE, AND/OR/NOT, таблицы истинности, порядок операций, скобки,
  законы де Моргана, перевод фраз в логику, ловушки с текстом и NULL.
- Таблица: `employees`.
- Заданий: 62 — `value` 30, `truth` 15, `rewrite` 11, `sql` 6. Разделы A–I.

**Урок 3. WHERE и фильтрация** ✅ (`id` 2)
- Темы: операторы сравнения, AND/OR/NOT, BETWEEN, IN, LIKE, NULL, DISTINCT.
- Таблицы: `employees`, `products`.
- Заданий: 131 — из них 50 дополнительных; `sql` 119, `pick` 7, `row` 5.
  Разделы A–H + «Доп.» к каждому.

**Урок 4. ORDER BY и LIMIT** ✅ (`id` 3)
- Темы: сортировка по одному и нескольким столбцам, NULL при сортировке, LIMIT и
  OFFSET, WHERE + ORDER BY + LIMIT, типичные ошибки.
- Таблицы: `products`, `orders`.
- Заданий: 35 (`sql`). Разделы A–F.

**Урок 5. Агрегатные функции** ✅ (`id` 4)
- Темы: COUNT(\*) vs COUNT(столбец) vs COUNT(DISTINCT), SUM, AVG, MIN, MAX (и на
  тексте, датах), агрегаты и NULL, ROUND, агрегат вместе с WHERE, почему агрегат нельзя
  в WHERE и рядом с обычным столбцом, целочисленное деление.
- Таблицы: `orders` (24 заказа от 13 покупателей, у 2 нет `amount`), `employees`
  (как в уроках 2–3).
- Заданий: 31 (`sql`). Разделы A–H: COUNT; SUM и AVG; MIN и MAX; ловушки NULL;
  COUNT(DISTINCT); сводка одним запросом; «найди ошибку»; арифметика над агрегатами (размах).
- Проверка по значениям (`check: values`): у агрегатов имена вроде `count`, `round`,
  ученик может дать свои через AS.
- Вопросы «прочитай результат» и «почему так» — в советах учителю, не в заданиях:
  тренажёр проверяет только результат запроса.

**Урок 6. GROUP BY и HAVING** ✅ (`id` 5)
- Темы: группа = строка результата; группировка по нескольким столбцам; WHERE до
  группировки, HAVING после; порядок выполнения запроса
  (FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT); NULL как отдельная
  группа; ORDER BY по агрегату и `NULLS LAST`; имя из `AS` не работает в HAVING.
- Таблицы: `employees` и `orders` (как в уроке 5), новая `sales` (13 продаж, у 2 нет
  `category` — для NULL-группы).
- Заданий: 38 (`sql`). Разделы A–H: один столбец; несколько агрегатов; несколько
  столбцов; HAVING; WHERE + GROUP BY + HAVING; NULL в GROUP BY; ORDER BY; «найди ошибку».
- Проверка по значениям (`check: values`), как в уроке 5. Интерпретация результатов —
  в советах учителю.
- Все 38 ответов прошли `/api/check` в браузере 2026-11-11.

### Дальше (предложение)

**Урок 7. JOIN** (`id` 6)
- Темы: ключи (первичный и внешний), INNER, LEFT, RIGHT, FULL, SELF JOIN;
  размножение строк при «один ко многим»; поиск «без пары» (`LEFT JOIN … IS NULL`);
  алиасы таблиц.
- Таблицы: нужна связанная пара/тройка (например, `employees` + `departments` +
  `projects`), впервые с внешними ключами.
- Подходят задания `pick`: «какие строки окажутся в результате JOIN».

**Урок 8. Подзапросы** (`id` 7)
- Темы: скалярный подзапрос, `IN (подзапрос)`, `EXISTS`, коррелированные подзапросы,
  подзапрос во `FROM`; ловушка `NOT IN` с NULL.
- Опирается на уроки 5–7.

**Урок 9. Операции над множествами** (`id` 8)
- Темы: UNION vs UNION ALL, INTERSECT, EXCEPT; совместимость столбцов; ORDER BY в конце.
- Небольшой урок; можно объединить с уроком 8 (см. открытые вопросы).

**Урок 10. CASE, COALESCE и работа с NULL** (`id` 9)
- Темы: CASE WHEN (простой и поисковый), CASE внутри агрегата, COALESCE, NULLIF,
  деление на ноль; NULL в сравнениях, сортировке и агрегатах — сводка.
- Подходят задания `value` из урока 2 для NULL-выражений.

**Урок 11. Оконные функции** (`id` 10)
- Темы: OVER, PARTITION BY, ORDER BY в окне; ROW_NUMBER, RANK, DENSE_RANK; LAG, LEAD;
  накопительная сумма; окно vs GROUP BY.
- Проверка: порядок строк при равных значениях уже учитывается (`order`-группы),
  но у RANK/ROW_NUMBER при равенстве результат может зависеть от движка — в ответах
  задавать однозначный порядок.

**Урок 12. CTE** (`id` 11)
- Темы: WITH, несколько CTE подряд, CTE вместо вложенных подзапросов, рекурсивный CTE
  (иерархия «начальник — подчинённый», ряд дат).
- Опирается на урок 8.

**Урок 13. DDL и DML** (`id` 12)
- Темы: CREATE TABLE, типы, ограничения (PRIMARY KEY, NOT NULL, UNIQUE, CHECK,
  FOREIGN KEY), ALTER TABLE, DROP; INSERT, UPDATE, DELETE, `RETURNING`; UPDATE/DELETE
  без WHERE.
- Нужно: проверка по состоянию таблицы после запроса (доработка 1). Подсветка
  вставленных и изменённых строк в таблице уже есть.

**Урок 14. Индексы, представления, транзакции** (`id` 13)
- Темы: представления (VIEW); индекс и `EXPLAIN` — на уровне «что это и зачем»;
  транзакции BEGIN / COMMIT / ROLLBACK; блокировки и уровни изоляции.
- Нужно: часть про блокировки и изоляцию требует нескольких соединений — PGlite их не
  даёт. Решение (2026-11-05): этот урок получает отдельный настоящий PostgreSQL на
  сервере (доработка 2); остальные уроки остаются на PGlite.

## Трек 2. SQL для аналитиков

Для тех, кто знает Excel: вопросы бизнеса про один интернет-магазин, ответы —
запросами. Один общий набор данных `shop` (`seed_ref`):

| Таблица | Столбцы | Строк |
|---|---|---|
| `customers` | customer_id, name, city, signup_date, channel | ~40 |
| `products` | product_id, name, category, price, cost | ~14 |
| `orders` | order_id, customer_id, order_date, status, promo_code, amount | ~107 |
| `order_items` | order_id, product_id, quantity, price | ~162 |

Даты заказов — с 2024-06-01 по 2025-12-25; статусы — `delivered`, `cancelled`, `returned`.

### Дальше (предложение)

**Урок 4. JOIN: соединяем таблицы** (`id` 104)
- Темы: INNER и LEFT JOIN как ВПР; размножение строк при соединении `orders` →
  `order_items` (и неверные суммы из-за него); клиенты без заказов.
- Главный навык: собрать выручку по категориям из трёх таблиц и не задвоить суммы.

**Урок 5. CASE: сегменты** (`id` 105)
- Темы: сегменты клиентов и заказов (маленький / средний / крупный чек), условные

**Урок 6. Даты и периоды** (`id` 106)
- Темы: `date_trunc`, `extract`, интервалы, недели и месяцы, «последние 30 дней»,

- Важно: `CURRENT_DATE` делает результат зависимым от дня запуска, а ожидаемые
  результаты посчитаны заранее. В заданиях задавать «сегодня» явно (например,
  `DATE '2025-12-31'`) и объяснить это в теории.

**Урок 7. CTE: запросы по шагам** (`id` 107)
- Темы: WITH, подзапросы, отчёт по шагам (сначала выручка по клиенту, потом сегменты

**Урок 8. Оконные функции** (`id` 108)
- Темы: ROW_NUMBER, RANK, LAG, накопительные суммы, рост к прошлому месяцу,
  первая покупка клиента.

**Урок 9. Бизнес-метрики** (`id` 109)
- Темы: средний чек, повторные покупки, удержание (когорты по месяцу регистрации),
  конверсия по каналам (`channel`), маржа (`price − cost`).
- Возможно, данных `shop` не хватит для когорт и конверсии — проверить при
  планировании урока; менять `shop` осторожно: на него опираются уроки 101–103.

**Урок 10. Итоговый проект: годовой отчёт магазина** (`id` 110)
- Десять вопросов директора: от данных к выводам. Каждый вопрос — отдельное задание
  с проверкой по значениям; выводы — в теории и ответах учителя (свободный текст не
  проверяем).

## Доработки тренажёра

1. **Проверка DML/DDL** (нужна уроку 13 «Основ»). Например: у задания есть
   `verify`-запрос, который выполняется после запроса ученика; сравнивается его

2. **Настоящий PostgreSQL для урока 14 «Основ»** (блокировки, изоляция): движок с
   теми же методами `run` / `reset` / `tables`, что `static/pg-engine.js`. Попытка уже
   была (ветка `feat/server-postgres`; в `main` — коммиты `aa2a64f`, `d35b340`, затем
   откат `81d4cee`) — разобрать, что из неё переиспользовать. На бесплатном Render
   базы нет — решить, где её держать.
3. Подсказки к типичным ошибкам новых тем (как подсказка про двойные кавычки,
   `hintFor` в `static/index.html`): «столбец должен быть в GROUP BY», «агрегат в WHERE»,
   неоднозначное имя столбца в JOIN.

## Прогрессия

```
Основы:     SELECT → логика → WHERE → сортировка → агрегаты → группы → JOIN
            → подзапросы → множества → CASE/NULL → окна → CTE → DDL/DML → транзакции
Аналитики:  разминка → итоги → сводные → JOIN → сегменты → даты → CTE → окна
            → метрики → годовой отчёт
```

Треки идут параллельно: аналитики проходят ту же грамматику быстрее и сразу на
вопросах бизнеса, основы — медленнее и с отдельными уроками на логику и NULL.
